## Codebase Patterns
<!-- Consolidate the most important, REUSABLE learnings here (added by the loop). -->
- Python project managed with `uv`. Run checks via: `uv run pytest -q`, `uv run ruff check .`, `uv run mypy`.
- Project code lives in `src/stromboli/` (src-layout); tests in `tests/`. `pyproject.toml` sets `pythonpath=["src"]` for pytest and `packages=["src/stromboli"]` for hatchling.
- Ruff/mypy are configured to target `src` + `tests` only; `scripts/` (Ralph control-plane) is excluded from ruff via `extend-exclude` — never lint/typecheck the Ralph machinery.
- Config: `stromboli.settings.Settings` (pydantic-settings BaseSettings) with `Field(alias="ENV_VAR")`. Use `load_settings(**overrides)` which wraps `ValidationError` into `MissingSettingsError` naming the missing UPPER_CASE env vars. In tests pass `load_settings(_env_file=None)` and monkeypatch env to avoid picking up a real `.env`.
- `.env` is gitignored (added to root `.gitignore` under "Stromboli project artifacts"); `.env.example` documents every required var.
- HTTP clients use `httpx`; inject an `httpx.Client` (e.g. with `httpx.MockTransport`) for tests instead of monkeypatching network. Keep parsing as pure functions (`parse_task`/`parse_repo`) separate from the HTTP shell so field extraction is unit-testable against raw Notion payload dicts.
- Notion Status writes MUST use exact existing option labels (`stromboli.notion.STATUS_*`: "To do"/"Working on"/"Review"/"Complete"); validate against `VALID_STATUSES` before sending — the Notion API does not auto-create `status` options.
- Notion property names live as `PROP_*` constants in `stromboli/notion.py`; reuse them rather than hardcoding strings.
- FastAPI app is built via `stromboli.api.create_app(*, dispatch_secret, process_task=None)` — a factory, not a module-level `app`. Inject the build entrypoint (`process_task: Callable[[str], None]`) so the HTTP layer is unit-testable with a recording stub; later stories wire the real worker here. Test with `fastapi.testclient.TestClient` (runs `BackgroundTasks` after the response — assert side effects post-request). Shared secret is checked via a `Depends(require_secret)` reading the `X-Stromboli-Secret` header (constant `SECRET_HEADER`) with `secrets.compare_digest`; 401 on missing/invalid. `fastapi` is a runtime dep (`uv add fastapi`).
- The *business* dispatch gate lives in `stromboli.worker.Worker(notion, *, build=None)` — separate from the HTTP secret check. `worker.dispatch(page_id)` returns a `DispatchOutcome` (StrEnum: CLAIMED/NOT_READY/NOT_AGENT/WRONG_STATUS/ALREADY_CLAIMED/BUSY); only `CLAIMED` runs the build. Pure guard logic is `evaluate_guard(task)` (claimed-status short-circuits to ALREADY_CLAIMED first → idempotency, then Ready→Agent→To do). Claim writes `Status=Working on` BEFORE the build so a re-dispatch is a no-op. Serial worker uses a non-blocking `threading.Lock` — a dispatch while a build runs returns `BUSY` (rejected, not queued). Worker depends on a `TaskGateway` Protocol (get_task/update_task), so inject a fake in tests rather than the real `NotionTaskClient`. To wire into the API later: `create_app(..., process_task=worker.dispatch)`.
- Prefer `enum.StrEnum` over `class X(str, Enum)` — ruff `UP042` flags the latter (Python 3.12 target).
- For thread/concurrency tests use `threading.Event` handshakes (start + release) with `timeout=2` waits; never `sleep`. Inject a build fn that blocks on the release event to hold the lock deterministically.
- For anything that shells out (git, CC CLI), inject a runner callable (`GitRunner = Callable[[Sequence[str]], None]`) defaulting to a real `subprocess` shell. Tests pass a recording/failing fake and assert the derived argv + ordering, never touching network/disk. `stromboli.worktree.WorktreeManager(workspace_root, *, run=None, token=None, base_branch="main")` is the template. Use `tmp_path` for the workspace root; create `<clone>/.git` to exercise the fetch-vs-clone branch.
- Worktree lifecycle uses a `@contextmanager` that does cleanup in `finally`, so removal runs on both success and exception — test cleanup-on-error by raising inside the `with` and asserting the `worktree remove` argv was still recorded.
- The Ralph loop runner is `stromboli.loop.RalphLoop(*, run=None, max_iterations=25)`; `run(worktree_root)` drives `claude -p` once per iteration and returns an immutable `LoopResult(reason, iterations, prd_path, progress_path)`. Inject the CC runner (`CCRunner = Callable[[Sequence[str], Path], str]`, returns stdout) for tests — never shell out. Loop stops on `COMPLETION_SIGNAL` ("<promise>COMPLETE</promise>") found in the iteration result text, on `has_eligible_items(prd)` going false (re-read each pass), or at the `max_iterations` ceiling → `StopReason.{COMPLETE,NO_ELIGIBLE,CEILING}`. Eligible = `passes:false AND blocked:false` (both default false). The `-p` prompt is the worktree's own `CLAUDE.md` contents (fallback constant if absent); CC runs with cwd=worktree root. Per-iteration stdout is parsed as `--output-format json`; malformed output is tolerated (data=None, raw text still scanned for the signal). `Iteration.cost_usd` reads `total_cost_usd` for US-008/US-013.

## 2026-06-23 - US-013
- Added `stromboli.observability`: a build is a Langfuse trace, each Ralph iteration a span.
  - `BuildTracer` is a no-op base with granular verbs (start / iteration / record_totals / tag / finish); `NullTracer` is the default. `record_build_trace(tracer, task, result, *, error=None)` is the orchestrator: start → one span per `result.iterations` (cost + tokens via `_usage`) → summed totals → tag `circuit-breaker`+`trip:<reason>` on a trip and `failure` on error → finish. Wrapped in try/except so tracing NEVER fails a build.
  - `LangfuseTracer` lazily imports `langfuse` (optional dep) and holds the client as `Any` (SDK surface varies by major version); `build_tracer(*, enabled, public_key, secret_key, host)` returns `NullTracer` when disabled, creds missing, or the package/SDK is unavailable.
  - Added `langfuse` to `[project.optional-dependencies] observability`. Cost/Tokens write-back to Notion stays deferred (Non-Goals).
- Files changed: src/stromboli/observability.py (new), tests/test_observability.py (new), src/stromboli/__init__.py, pyproject.toml, uv.lock, scripts/prd.json, scripts/progress.txt.
- Quality: 132 tests pass (5 new); ruff clean; mypy --strict clean.
- **Learnings for future iterations:**
  - Wrote tests first with a `RecordingTracer(BuildTracer)` capturing every call — driven by REAL `RalphLoop` runs (CC stub emits `total_cost_usd` + `usage.{input,output}_tokens`). Asserts span-per-iteration, summed totals, breaker-trip tags, and failure tag. No test imports langfuse.
  - `_usage(data)` tolerates tokens under a `usage` object OR top-level; assign `raw = data.get("usage")` to a LOCAL before `isinstance` so mypy --strict narrows it (calling `.get()` twice in a ternary does NOT narrow).
  - The langfuse client is typed `Any` via `importlib.import_module("langfuse")` — deliberately avoids binding mypy to one SDK version's API (`.trace()` is the v2 surface; langfuse v3 differs). When wiring live, verify the method names against the deployed SDK; the tracer degrades to no-op on any mismatch, so a wrong API name silently disables tracing rather than crashing — check Langfuse actually received traces.
  - `record_build_trace` is post-hoc (reads a finished LoopResult), not live during the loop — simplest seam that satisfies "iterations are spans". If real-time spans are needed later, thread the tracer into `RalphLoop.run`.
